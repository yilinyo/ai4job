## 失败与诊断

### F-001：简历仓库没有数据时页面无空态或错误提示

- 首个失败检查点：TC-003 第 1 步。
- 复现步骤：登录 `admin` 账号，访问 `http://1.12.218.126:8081/#/resume/repos`，等待页面稳定。
- 预期结果：当账号没有简历仓库时，内容区应显示“暂无数据”及可选的创建引导；若请求失败，应展示可理解的失败信息和重试方式。
- 实际结果：页面仅显示搜索、求职类型和“创建仓库”控件，列表区域完全空白。
- 失败证据：Chrome 页面截图；无任何仓库卡片、表格、加载状态或空态文案。面试题库的同类空数据页面可正常显示“暂无数据”。
- 可能问题层：UI | API | 数据
- 建议下一步排查：确认列表 API 返回值、前端空数组分支和请求失败处理；与题库列表统一空态组件/文案。

### F-002：岗位仓库没有数据时页面无空态或错误提示

- 首个失败检查点：TC-005 第 1 步。
- 复现步骤：登录 `admin` 账号，访问 `http://1.12.218.126:8081/#/job-postings/list`，等待页面稳定。
- 预期结果：当账号没有岗位时，内容区应显示“暂无数据”及新增岗位引导；若请求失败，应展示错误信息。
- 实际结果：页面只保留搜索控件与“新增岗位”按钮，岗位列表区域完全空白。
- 失败证据：Chrome 无障碍树仅识别出筛选控件和“新增岗位”，未识别列表、空态、分页或错误提示。
- 可能问题层：UI | API | 数据
- 建议下一步排查：核验岗位列表 API 响应，并补齐空数据、请求失败及加载中状态。

### F-003：登录失败时前端控制台出现 Vuex Action 异常

- 首个失败检查点：登录页提交阶段（首轮因自动填充值与手动输入叠加导致账号为 `adminadmin`，登录失败）。
- 复现步骤：以无效凭据提交登录（本次仅发生一次非预期尝试）。
- 预期结果：显示登录失败提示，不应产生框架级异常。
- 实际结果：控制台记录 `ERR_ACTION_ACCESS_UNDEFINED`，并附带 `Could not perform action Login`；随后显示“用户名或密码错误”。正确凭据登录可成功进入后台。
- 失败证据：Chrome 控制台错误日志，来源 `chunk-libs.d54a7555.js`。
- 可能问题层：状态管理 | 登录 Action
- 建议下一步排查：检查登录 Vuex module 的 `@Action` 中是否通过 `this.someMutation()` / `this.someGetter` 访问非动态模块成员，改为 `this.context.commit()` / `this.context.getters[]`。

### F-004：后台右上角用户头像为破图

- 首个失败检查点：登录后的工作台 Header。
- 复现步骤：登录后进入 `/#/dashboard`，观察右上角用户头像区域。
- 预期结果：显示用户头像，或在未设置头像时显示默认头像/用户名占位。
- 实际结果：显示破图占位。页面唯一的图片元素 `src` 为 `?imageView2/1/w/80/h/80`，浏览器报告 `naturalWidth: 0`。
- 失败证据：Chrome DOM 图片状态读取结果：`complete: true`、`naturalWidth: 0`。
- 可能问题层：UI | 用户资料数据 | 静态资源
- 建议下一步排查：对空头像 URL 使用本地默认头像；不要对空 URL 直接拼接图片处理查询参数。

### F-005：线上侧边栏暴露大量模板演示功能

- 首个失败检查点：登录后的左侧导航。
- 复现步骤：登录后查看任意后台页面的侧边栏。
- 预期结果：生产导航应仅保留求职业务模块及明确需要的系统入口。
- 实际结果：除“个人信息、简历仓库、岗位仓库、面试题库”外，仍展示“引导页、权限测试页、图标、组件、图表、路由嵌套、表格、综合实例、分栏、错误页面、错误日志、Excel、Zip、PDF、换肤、粘贴板、国际化、外链”等模板菜单。
- 失败证据：Chrome 无障碍树中的线上菜单项。
- 可能问题层：路由 | 菜单配置 | 发布配置
- 建议下一步排查：生产路由白名单仅保留业务模块；开发示例路由应移除或按环境禁用。
