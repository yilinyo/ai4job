## Context

登录接口当前将“用户名不存在”和“密码错误”都映射成 `ErrUnauthorized`，而 handler 再统一翻译为 `40100 / 未登录`。这会让登录失败场景和 token 失效场景混淆，前端只能看到错误的语义提示。

前端请求拦截器会直接展示后端的 `message`，因此这类问题必须在后端错误语义层面修正，而不是只在前端做兜底文案替换。

## Goals / Non-Goals

**Goals:**

- 为登录凭证错误提供独立业务语义。
- 让“未登录 / token 失效”和“用户名或密码错误”可区分。
- 保持前端不需要猜测后端场景即可展示正确提示。

**Non-Goals:**

- 不区分用户名不存在与密码错误的对外提示。
- 不修改 token 过期、登出、权限不足等其它认证语义。

## Decisions

### 1. 复用一个登录失败文案，避免暴露账号存在性

对外统一返回“用户名或密码错误”，不区分是用户名不存在还是密码错误。

理由：既满足用户提示，也避免暴露账号是否存在。

### 2. 认证缺失语义继续保留给 token 失败

`40100` 继续表示未登录、token 无效或 token 过期，不再承载登录凭证错误。

理由：这让前端会话失效逻辑和登录表单错误逻辑能明确分流。

### 3. 登录失败错误码应避免触发自动登出逻辑

前端通用请求拦截器中的自动登出分支只应针对 token 类错误，不应被登录凭证错误误触发。

## Risks / Trade-offs

- [Risk] 新增登录失败码后，前端可能需要补充对应错误提示分支。→ Mitigation: 保持 message 统一为“用户名或密码错误”，前端主要依赖展示文案即可。
- [Risk] 如果 handler 仍然一刀切映射 `ErrUnauthorized`，语义会继续混淆。→ Mitigation: 登录场景需要单独错误映射。
