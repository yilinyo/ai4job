## 为什么要做

当前登录接口在“用户名不存在”或“密码错误”时，后端统一返回 `40100` 和“未登录”。这会让用户在主动执行登录时收到错误的语义反馈，误以为自己处于 token 失效或会话未登录状态，而不是凭证校验失败。

现有前端请求拦截器会直接展示后端返回的 `message`，因此只要后端仍把登录失败映射为“未登录”，前端就无法准确提示“用户名或密码错误”。同时，前端注释中已经保留了 `50005: username or password is incorrect` 这一类登录失败语义，但后端当前并未提供对应的错误码与响应约定。

本次变更需要为登录凭证错误建立独立且明确的业务错误语义，使“未登录 / token 无效”和“登录凭证错误”在状态码与文案层面分离。

## 变更内容

- 为登录时的凭证校验失败引入独立的业务错误语义，不再复用 `40100 / 未登录`。
- 将“用户名不存在”和“密码错误”对外统一收敛为“用户名或密码错误”，避免暴露账号存在性。
- 保持 `40100` 继续只用于未登录、token 无效或受保护接口认证失败场景。
- 调整登录接口相关测试与文档，使前后端对错误码含义保持一致。

## 能力定义

### 新增能力

- `login-credential-error-response`: 登录凭证错误返回独立业务错误码和“用户名或密码错误”文案。

### 修改能力

- `login-register-entry`: 登录页在收到凭证错误时应向用户展示明确的登录失败语义，而不是“未登录”。

## 影响范围

- 影响后端错误码定义与领域错误映射。
- 影响 `user` 登录 service / handler 的错误返回语义。
- 影响前端登录失败时的实际提示文案体验。
- 影响登录相关后端测试与接口文档说明。
- 影响前端通用请求拦截器对业务错误码的理解边界，需确认新增登录失败错误码不会误触发“自动登出”逻辑。

## 验收关注点

- 登录时输错密码，页面提示应为“用户名或密码错误”，不得继续显示“未登录”。
- 登录时输入不存在的用户名，页面提示也应统一为“用户名或密码错误”。
- 未携带 token、token 失效、访问受保护接口失败时，仍应继续返回 `40100` 这一类认证缺失语义。
- 前端收到登录凭证错误时，只提示错误，不应触发清 token、强制刷新或跳转登录等“会话失效”分支。

## 非目标

- 不区分“用户名不存在”和“密码错误”两种对外提示。
- 不在本次变更中修改 token 过期、登出、权限不足等其它认证相关错误语义。
- 不扩展找回密码、账号锁定、登录限流等安全策略。
