## Context

当前登录页与注册页已经升级为蓝白企业级认证页布局，使用浅蓝渐变背景、白色卡片和蓝色强调色来建立产品第一印象。但登录后的主框架仍沿用模板默认的深色侧边栏变量和样式，包括深灰背景、浅灰文字以及深色 Logo 区，导致用户从认证页进入系统后出现明显的风格跳变。

同时，侧边栏菜单标题当前依赖 `SidebarItem` 中统一的 `$t('route.' + meta.title)` 渲染方式，但业务路由配置中混用了国际化 key 与中文直写标题。例如简历仓库、岗位列表等入口使用中文作为 `meta.title`，会在国际化词条缺失时暴露出 `route.*` 原始 key。这个问题不仅影响显示一致性，也使新增业务入口时容易继续复制不稳定配置。

本变更聚焦于“登录后基础导航层”的视觉与命名一致性，不扩展到整站主题重构，也不调整现有业务页面层级。

## Goals / Non-Goals

**Goals:**

- 让左侧侧边栏在视觉上延续登录页、注册页的蓝白企业级风格。
- 统一侧边栏背景、文字、hover、激活态和 Logo 区的样式语言，消除深色模板残留。
- 统一侧边栏路由标题配置方式，避免 `route.*` 原始 key 泄漏到 UI。
- 为“简历仓库”和“岗位仓库”选用更贴合业务语义且风格一致的图标。
- 保持现有导航层级和主路由结构不变，以较小代价完成视觉与文案统一。

**Non-Goals:**

- 不重构顶部导航、TagsView、内容区卡片或全站主题变量体系。
- 不在本次变更中新增主题切换、深浅模式切换或品牌换肤能力。
- 不重新设计岗位列表、简历仓库列表、面试题库等业务页面内部布局。
- 不调整一级 / 二级菜单结构，不把本次变更扩展为信息架构重组。

## Decisions

### 1. 仅收敛侧边栏相关样式，不扩展为全局主题重构

本次优先调整 `Sidebar`、`SidebarItem`、`SidebarLogo` 以及其依赖的侧边栏颜色变量，使用户最先感知到的导航框架与认证页风格连续。

理由：用户提出的问题集中在侧边栏与登录 / 注册风格不一致；如果扩展为全局主题重构，会把范围放大到 Navbar、TagsView、内容区卡片和图表色系，超出当前 change 的独立粒度。

替代方案是一次性重构全部布局色彩体系。该方案更彻底，但需要额外 PRD 和更大的验证范围，不适合本次小而清晰的 UI 一致性调整。

### 2. 继续沿用现有 Sidebar 渲染机制，但统一 `meta.title` 的 key 策略

当前侧边栏标题渲染集中在 `SidebarItem.vue` 中，统一使用 `$t('route.' + meta.title)`。本次不修改这套机制，而是将业务路由中混用中文直写的 `meta.title` 调整为稳定的 route key，并补齐对应语言包词条。

理由：改动标题来源比修改全站侧边栏、面包屑、标签页、权限页等多处使用 `$t('route.' + meta.title)` 的逻辑风险更低，也更符合仓库中其它菜单的既有模式。

替代方案是在组件层为中文直写标题增加 fallback 逻辑，例如“翻译失败则直接显示原文”。该方案能兜底，但会继续允许 key 与文案混用，后续新增菜单时仍容易失控。

### 3. “简历仓库”和“岗位仓库”使用业务语义更明确的图标组合

本次将为“简历仓库”使用偏文档 / 资料语义的图标，将“岗位仓库”使用偏职位机会 / 招聘语义的图标，并保持两者在侧边栏中的强调色、尺寸和视觉风格一致。

理由：这两个入口是当前求职流程系统中最核心的一组一级导航，图标应当帮助用户快速区分“我的简历资产”和“外部岗位机会池”。

替代方案是继续沿用模板默认的通用列表图标。该方案实现成本最低，但识别度和产品表达偏弱。

### 4. 激活态采用“浅色容器 + 蓝色强调”而不是仅改文字颜色

新侧边栏激活态将以白底或浅蓝底承载当前菜单，再辅以蓝色文字和图标，而不是只保留当前模板的“深色底 + 蓝色字”高亮方式。

理由：登录页和注册页已经建立了白卡片 + 蓝强调的视觉语法，侧边栏激活态延续这套语言能更自然地连接认证页与业务页。

替代方案是只修改背景底色和文字色变量。该方案更省事，但很可能仍保留旧模板的层次感，不足以体现“蓝白统一”的变化。

### 5. 保持导航层级不变，只修正文案与视觉表达

本次 change 不把“简历管理 / 简历仓库 / 岗位仓库”等入口重新分组或挪动层级，只处理现有入口的视觉与文案一致性。

理由：当前需求明确聚焦“样式一致”和“route 前缀问题”，没有提出导航信息架构重组；如果同时调整层级，容易与既有 `resume-navigation-structure`、`job-posting-library-management` 的能力边界交叉。

## Risks / Trade-offs

- [Risk] 蓝白侧边栏如果过于接近内容区背景，可能导致导航边界变弱。→ Mitigation：保留轻边框、阴影或激活容器层次，确保导航区与内容区可分辨。
- [Risk] 仅调整业务路由标题 key，未补齐多语言词条会导致其它语言出现缺失。→ Mitigation：至少同步补齐当前已启用语言包中的新 route key，避免只在中文环境正常。
- [Risk] 更换图标后与旧页面截图、文档或用户记忆存在轻微偏差。→ Mitigation：优先选用与现有业务语义接近的图标，并保持同一导航位置与名称，减少认知迁移成本。
- [Risk] 侧边栏变量改动可能波及折叠态、子菜单和 hover 效果。→ Mitigation：任务和验证中单独覆盖展开 / 折叠态、一级 / 二级菜单以及激活 / hover 场景。
