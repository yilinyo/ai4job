## Context

登录页和注册页均使用双列认证页布局，并在 960px 以下切换为单列。当前 520px 断点仍保留较大的外边距、品牌内容与卡片圆角；登录页的统计信息会改为纵向堆叠，注册页验证码操作会改为纵向堆叠。详见 `proposal.md` 与 `auth-page-mobile-layout` 规格。

## Goals / Non-Goals

**Goals:**

- 在手机窄屏将认证表单放在更靠前的位置，控制留白并消除横向溢出风险。
- 保留既有蓝白品牌语言、表单字段、校验、路由和 API 请求行为。
- 让注册验证码输入与发送操作在一行中拥有可预测、可触控的宽度。

**Non-Goals:**

- 不重做桌面和平板布局，不变更登录/注册业务字段或邮箱验证码倒计时逻辑。
- 不新增响应式框架、全局样式依赖或独立移动端路由。

## Decisions

### 1. 以 520px 为手机专项断点，并覆盖现有移动端规则

`960px` 以下继续使用现有单列结构；`520px` 以下进一步缩小页面 padding、卡片 padding 和标题字号，品牌区仅保留标识、标题和简短说明。品牌统计/步骤区直接隐藏，而非改为单列，避免辅助信息使表单下移。

选择在页面作用域内追加精确断点，避免影响后台页面。备选的全局移动 CSS 会扩大影响范围，且不适合认证页特有的信息优先级。

### 2. 验证码行保持 flex 单行并限制发送按钮宽度

注册页窄屏下验证码行继续使用 `display: flex`；输入框使用 `min-width: 0` 参与收缩，发送按钮用固定的紧凑宽度与 `flex-shrink: 0` 保证文案、倒计时和加载状态不会挤压或换行。

选择单行而非纵向堆叠，减少字段到操作之间的视线和触控距离，也符合规格的稳定布局要求。

### 3. 登录和注册采用同一移动信息层级

两页在手机端均保留品牌标识、操作标题和核心表单，隐藏各自的三项辅助块，并保持桌面端色彩、边框和按钮样式。这确保两条认证路径在移动端体验一致。

## Risks / Trade-offs

- [隐藏统计/步骤信息会减少首次访问时的功能说明] → 保留品牌、标题和摘要，且桌面与平板继续展示完整信息。
- [窄屏发送按钮文案较长] → 固定紧凑宽度并禁止其收缩，输入框可在剩余空间内伸缩。
- [多层 scoped 样式覆盖顺序出错] → 在原有 520px 媒体查询中就近覆盖，并通过桌面与手机截图检查。

## Migration Plan

1. 在登录、注册页面补充窄屏样式规则。
2. 运行前端静态检查和生产构建。
3. 使用手机与桌面视口检查认证流程；若出现样式回归，移除对应 520px 覆盖即可回滚，无数据迁移影响。
