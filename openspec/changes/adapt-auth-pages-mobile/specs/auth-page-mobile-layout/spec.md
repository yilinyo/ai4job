## Purpose

定义登录页与注册页在手机窄屏上的布局、触控和信息优先级要求，使用户无需横向滚动或穿过冗长的装饰区域即可完成认证。

## ADDED Requirements

### Requirement: 认证表单在手机窄屏必须优先可用

系统 MUST 在视口宽度不超过 520px 时，将登录页和注册页呈现为单列、全宽可用的认证流程；表单、主操作按钮和登录/注册切换入口不得产生横向滚动或被容器裁切。

#### Scenario: 用户在手机上打开登录页
- **WHEN** 用户以宽度不超过 520px 的设备访问登录页
- **THEN** 用户可在不横向滚动的情况下看到并操作用户名、密码、登录按钮和注册入口
- **AND** 输入框与主按钮具有适合触控操作的稳定尺寸

#### Scenario: 用户在手机上打开注册页
- **WHEN** 用户以宽度不超过 520px 的设备访问注册页
- **THEN** 用户可在不横向滚动的情况下完成用户名、密码、邮箱和验证码输入并提交注册
- **AND** 返回登录入口保持可见且可操作

### Requirement: 手机窄屏必须收敛认证页辅助品牌信息

系统 MUST 在视口宽度不超过 520px 时保留产品识别和页面标题，但将登录页的统计信息与注册页的步骤信息收敛，避免装饰性内容挤占认证表单的首屏空间。

#### Scenario: 手机用户查看认证页顶部
- **WHEN** 用户以宽度不超过 520px 的设备打开登录页或注册页
- **THEN** 页面保留品牌标识和与当前操作相关的标题
- **AND** 多项统计或步骤信息不以纵向堆叠方式延长页面

### Requirement: 注册验证码操作在手机窄屏必须保持可操作

系统 MUST 在视口宽度不超过 520px 时让验证码输入框和发送验证码按钮保持单行布局，且两者均不得溢出表单容器。

#### Scenario: 用户请求邮箱验证码
- **WHEN** 用户以宽度不超过 520px 的设备在注册页输入有效邮箱
- **THEN** 用户可在同一行看到验证码输入框和发送验证码按钮
- **AND** 倒计时或加载状态不会改变该行的布局宽度或遮挡输入框
