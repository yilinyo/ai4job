## Context

当前简历版本编辑页使用 textarea + 编辑/预览切换，题库新增/编辑弹窗也使用独立 textarea 来编辑题目内容和答案解析。仓库里已经存在通用的 `MarkdownEditor` 侧边栏模板，它具备同屏编辑与预览能力，更适合承载这类 Markdown 输入场景。

## Goals / Non-Goals

**Goals:**
- 统一简历编辑页与题库编辑弹窗的 Markdown 编辑体验。
- 复用现有 `MarkdownEditor` 侧边栏模板，减少重复实现。
- 保留现有 Markdown 内容结构、图片粘贴能力和保存结果。
- 尽量不改动只读预览页面和后端数据结构。

**Non-Goals:**
- 不重写 Markdown 渲染器。
- 不修改后端接口或数据库结构。
- 不把所有只读预览页也迁移到同一种编辑器。

## Decisions

1. **复用现有 `MarkdownEditor` 作为统一编辑壳**
   - 原因：项目内已经有成熟的 Toast UI Editor 封装，具备侧边栏预览和工具栏能力。
   - 备选方案：继续保留 textarea + 单独预览切换，或新写一套编辑器组件。
   - 取舍：复用现有组件最省实现成本，也最符合“侧边栏模板”的目标。

2. **只改编辑入口，不改只读预览链路**
   - 原因：简历详情页、题目详情页和 PDF 导出已经有稳定的 Markdown 渲染链路。
   - 备选方案：同步重构所有 Markdown 预览页。
   - 取舍：这次变更聚焦编辑体验，避免把风险扩散到阅读与导出链路。

3. **编辑器与表单之间增加薄适配层**
   - 原因：现有表单提交仍然依赖纯文本字段，而编辑器是独立组件。
   - 备选方案：直接改造表单为完全受控的编辑器状态，或推翻现有字段结构。
   - 取舍：薄适配层可以保留原有校验、保存和预填逻辑，改动面更小。

4. **保留 Markdown 图片粘贴行为**
   - 原因：题库编辑当前依赖图片粘贴转 Markdown 的习惯用法。
   - 备选方案：仅保留工具栏插图，不处理粘贴内容。
   - 取舍：保留粘贴行为更符合用户现有使用路径，也避免训练成本。

## Risks / Trade-offs

- [编辑器容器较重] → 题库弹窗和简历编辑页可能需要重新调整高度、滚动和宽度，避免预览区挤压输入区。
- [表单同步复杂] → 通过薄适配层统一编辑器内容与表单字段，减少双向绑定混乱。
- [粘贴图片行为差异] → 保留并验证图片粘贴/插入逻辑，必要时回退到现有 textarea 方案。
- [组件复用带来局部样式差异] → 通过页面级样式微调保持与现有蓝白主题一致。

## Migration Plan

1. 先在简历版本编辑页接入统一 MarkdownEditor，确认保存内容与详情页渲染一致。
2. 再在题库新增/编辑弹窗接入同一编辑模板，确认内容、答案解析与图片粘贴行为一致。
3. 如出现编辑器容器布局问题，回退到原 textarea 方案，不影响现有数据。
