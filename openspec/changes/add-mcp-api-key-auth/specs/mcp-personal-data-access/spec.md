## Purpose

通过受个人 API Key 鉴权的 MCP 工具，让外部 MCP 客户端在严格用户隔离的边界内读取用户的面试与题库数据，并将结构化题目写回用户自己的题库。

## ADDED Requirements

### Requirement: MCP 服务必须通过个人 API Key 建立调用用户身份
MCP 服务 MUST 要求每个工具调用携带有效且未撤销的个人 API Key，并 MUST 将调用身份绑定为该 Key 所属用户。无效、缺失或已撤销的 Key MUST 使调用失败，且系统 MUST NOT 执行工具业务逻辑。

#### Scenario: 有效 Key 调用 MCP 工具
- **WHEN** MCP 客户端使用有效的 `ai4job-` Key 调用工具
- **THEN** 系统将该 Key 所属用户作为当前调用用户
- **AND** 工具仅在该用户的数据范围内执行

#### Scenario: 无效或撤销 Key 调用 MCP 工具
- **WHEN** MCP 客户端使用缺失、格式错误、无效或已撤销的 Key 调用工具
- **THEN** 系统返回认证失败
- **AND** 系统不返回任何业务数据且不产生业务写入

### Requirement: MCP 必须提供按简历版本查看面试记录的工具
MCP 服务 MUST 提供一个工具，使当前用户按其名下简历版本查看关联投递记录及面试进展。工具输入中的简历版本标识 MUST 归属于当前调用用户；返回记录 MUST 包含关联简历版本、投递岗位快照、当前状态和面试进展信息。

#### Scenario: 用户查看自己简历版本的面试记录
- **WHEN** MCP 客户端提供当前用户名下的简历版本标识
- **THEN** 系统返回该简历版本关联的投递记录和面试进展
- **AND** 每条记录包含岗位快照、当前状态和对应进展节点

#### Scenario: 用户查看他人简历版本的面试记录
- **WHEN** MCP 客户端提供不属于当前调用用户的简历版本标识
- **THEN** 系统拒绝该调用或返回未找到结果
- **AND** 系统不暴露该简历版本、投递记录或面试进展信息

### Requirement: MCP 必须提供当前用户全部面试流程状态的工具
MCP 服务 MUST 提供一个工具，返回当前调用用户全部投递记录的当前状态及其面试流程节点，并包含关联简历版本与岗位快照，供客户端汇总用户的面试进展。

#### Scenario: 用户查看全部面试流程状态
- **WHEN** MCP 客户端调用全部面试流程状态工具
- **THEN** 系统返回当前用户的投递记录、关联简历版本、岗位快照、当前状态和面试进展节点
- **AND** 系统不返回其他用户的记录

### Requirement: MCP 必须提供当前用户题库查询工具
MCP 服务 MUST 提供一个工具，支持当前调用用户按关键词、标签、难度、题型、掌握状态或收藏状态筛选其题库，并支持分页返回题目基础信息与内容。

题库查询与创建工具的 JSON Schema MUST 显式声明以下枚举值，且每个枚举值 MUST 提供可读说明：

- `difficulty`：`easy`（简单）、`medium`（中等）、`hard`（困难）。
- `questionType`：`knowledge`（知识点）、`scenario`（场景）、`coding`（编程）、`algorithm`（算法）、`project`（项目）、`behavior`（行为）、`discussion`（开放讨论）。
- `masteryStatus`：`unreviewed`（未复习）、`weak`（薄弱）、`normal`（一般）、`mastered`（已掌握）。

#### Scenario: 用户查询自己的题库
- **WHEN** MCP 客户端提供有效筛选条件或分页参数调用题库查询工具
- **THEN** 系统返回仅属于当前用户的匹配题目及分页信息

#### Scenario: MCP 客户端发现题库枚举参数
- **WHEN** MCP 客户端通过 `tools/list` 获取题库查询或创建工具的输入 Schema
- **THEN** `difficulty`、`questionType` 和 `masteryStatus` 均以 JSON Schema `enum` 返回全部合法值及其说明
- **AND** 客户端可据此构造符合既有题库字段约束的请求

### Requirement: MCP 必须支持向当前用户题库批量新增题目
MCP 服务 MUST 提供一个工具，允许当前调用用户一次新增一条至五十条题目。每条题目 MUST 满足现有题库的必填字段和枚举约束；系统 MUST 将题目归属为当前调用用户，且调用者不得指定或覆盖题目所属用户。

#### Scenario: 用户新增一条题目
- **WHEN** MCP 客户端提交一条满足题库字段约束的题目
- **THEN** 系统在当前用户题库创建该题目
- **AND** 返回新题目的标识和创建结果

#### Scenario: 用户批量新增多条题目
- **WHEN** MCP 客户端提交二至五十条均满足字段约束的题目
- **THEN** 系统为当前用户创建全部题目
- **AND** 返回每条题目的标识和创建结果

#### Scenario: 批量请求含有无效题目
- **WHEN** MCP 客户端提交的任一题目缺少必填字段、枚举值无效或数量超过五十条
- **THEN** 系统拒绝整个批量请求并返回可定位的校验错误
- **AND** 系统不创建该请求中的任何题目

### Requirement: MCP 工具必须强制执行用户数据隔离
所有 MCP 读取和写入工具 MUST 从已验证 API Key 推导当前用户身份，而不是信任客户端提供的用户标识。工具 MUST 对请求涉及的既有资源验证归属关系。

#### Scenario: 客户端伪造用户标识
- **WHEN** MCP 客户端在工具参数中传入其他用户标识或尝试通过资源标识跨用户访问
- **THEN** 系统忽略客户端提供的用户标识并按 API Key 所属用户处理
- **AND** 系统拒绝或隐藏不属于该用户的资源
