## Why

当前系统只能通过浏览器中的 JWT 会话访问个人求职数据，无法让用户安全地将自己的面试记录和题库接入 MCP 客户端或自动化工作流。需要提供用户可自行管理、可撤销且不暴露明文存储的 API Key，以在不共享网页登录凭据的前提下建立 MCP 的个人数据访问边界。

## What Changes

- 在个人中心增加开发者访问入口，允许已登录用户创建、查看 Key 前缀、创建时间和过期时间，并撤销和重新生成自己的 API Key；新 Key 使用 `ai4job-` 前缀，创建时可选择 30 天、60 天、90 天或永不过期，完整明文只在创建时显示一次。
- 新增 API Key 的服务端数据模型和鉴权中间件，将有效 Key 映射为唯一的当前用户身份，并记录必要的生命周期与最近使用信息。
- 新增受 API Key 鉴权的 MCP 服务入口，提供查看当前用户指定简历关联面试记录、查看全部面试流程状态、查看题库，以及向当前用户题库批量新增题目的工具。
- MCP 读取和写入均以 API Key 所属用户为唯一数据范围；调用者不能通过请求参数读取或写入其他用户资源。
- 为 MCP 批量新增题目定义输入校验、单次上限和失败返回规则，复用现有题库的字段与领域约束。

## Capabilities

### New Capabilities
- `personal-api-key-management`: 用户在个人中心安全地申请、展示、撤销和重新生成个人 API Key 的生命周期管理能力。
- `mcp-personal-data-access`: 通过 API Key 鉴权的 MCP 服务，为 Key 所属用户提供面试记录、面试流程、题库读取和题库批量写入工具。

### Modified Capabilities
- `user-profile-management-as-top-level-entry`: 个人中心增加开发者访问区域，用于管理个人 API Key，且不影响现有个人信息资料编辑能力。

## Impact

- 后端：新增 API Key 领域模型、迁移、仓储、应用服务、鉴权中间件、HTTP/MCP 路由和相应测试；现有面试、投递、简历版本和题库服务需要提供按当前用户范围访问的 MCP 适配层。
- 前端：个人中心、模型、API 与状态管理增加 API Key 管理界面和一次性明文展示交互。
- 数据与安全：新增 API Key 持久化记录，只保存密钥哈希和可显示前缀；MCP 请求不复用浏览器 Cookie 或 JWT，并需要防止跨用户资源访问和敏感信息进入日志。
- 对外接口：新增 MCP 服务地址及其工具契约；现有浏览器 API 的认证方式和返回结构保持兼容。
